# Computational Thinking

## Definition

Computational thinking is breaking a problem into parts, spotting patterns, ignoring irrelevant detail, and expressing a solution as clear, repeatable steps — whether or not a computer is involved.

## Why it matters here

It is the bridge between "I understand the problem" and "I can build a solution." A learner who can decompose and sequence can code in any language; one who cannot will memorize syntax and still be stuck.

## The four moves (Wing's pillars, made concrete)

1. **Decomposition** — split a big task into small tasks.
2. **Pattern recognition** — notice what repeats.
3. **Abstraction** — keep what matters, drop the rest.
4. **Algorithm** — write the steps in order, including the decisions.

## Common misconceptions

- *"Computational thinking = coding."* It is the thinking that precedes code; you can practice it with a recipe or a bus route.
- *"The first plan should be the final plan."* Algorithms are drafted and refined.
- *"Edge cases are optional."* The "what if it's empty / wrong / zero?" cases are where real thinking happens.

## Tutor moves

- "What are the smaller steps inside this step?"
- "Where does this pattern repeat? Could one rule handle all of them?"
- "What can we ignore for now?"
- "Walk me through it as if I were the computer — what happens first, then next?"
- "What if the input is empty, or huge, or wrong?"

## Mission hooks

- Before writing Python, learners write the algorithm in plain language (or numbered steps) and dry-run it by hand.
- "Predict the output" activities force mental execution before running code.
- Debugging challenges train pattern recognition on real errors.

## Mastery rubric

| Level | What it looks like |
|------|--------------------|
| Awareness | Follows a given step-by-step process; recognizes an obvious pattern. |
| Application | Decomposes a small problem and drafts an algorithm with guidance. |
| Independence | Decomposes, abstracts, and handles edge cases for a new problem unaided. |
| Leadership | Helps others break down problems and spot patterns. |

## Assessment signals

Clarity of decomposition; whether patterns were reused rather than repeated; whether edge cases were considered before coding.
