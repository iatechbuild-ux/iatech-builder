# Research — How to Read This Folder

> v2.0 note: In v1.0 every file here was the same template with one sentence changed. That is fixed. Each competency below has genuinely distinct content. What they share is a *structure*, not their words.

Each research file translates one competency into something the product can actually build and assess. Every file follows the same seven-part structure so authors and engineers know where to look:

1. **Definition** — IATECH's working definition of the competency.
2. **Why it matters here** — the specific reason this competency serves problem-solving.
3. **The model / cycle** — the concrete thinking or building sequence the learner practices.
4. **Common misconceptions** — the specific wrong ideas learners (and tutors) bring, and the correction.
5. **Tutor moves** — the specific questions and facilitation behaviors that develop it.
6. **Mission hooks** — concrete examples of how it shows up in real missions.
7. **Mastery rubric** — what Awareness / Application / Independence / Leadership look like *for this competency* (per [`00-VISION/mastery-model.md`](../00-VISION/mastery-model.md)).

## The competency set

**Thinking:** critical-thinking · systems-thinking · computational-thinking · problem-solving
**Value:** design-thinking · product-thinking
**Building:** web-development · python
**AI:** ai-literacy · prompt-engineering

## The rule that keeps research honest

No competency is taught as an isolated subject. Each one is developed *inside missions*, assessed through *artifacts and explanation*, and made visible through *badges and portfolio tags*. If a research idea cannot be expressed as a tutor move, a mission hook, and a rubric row, it is not ready to enter the curriculum.
