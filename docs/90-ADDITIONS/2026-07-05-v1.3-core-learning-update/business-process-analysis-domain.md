# Business and Process Analysis Domain

## Purpose

IATECH exists to ease business processes and build future tech enthusiasts who solve process problems.

This domain teaches learners to diagnose workflows before recommending technology.

## Core Principle

> Diagnosis before prescription.

## What Students Learn

- Process mapping
- Workflow observation
- User interviews
- Requirements gathering
- Root cause analysis
- Bottleneck identification
- Process improvement
- Tool selection
- Solution documentation

## Why It Matters

A student should not always say, "Let's build an app."

They should ask:

- What process is broken?
- Who is affected?
- What takes too long?
- Where do errors happen?
- What information is missing?
- Is the best solution a website, dashboard, form, CMS, automation, training, or policy change?

## Example Missions

- Map a school admission process.
- Improve a small business order process.
- Design a better event registration workflow.
- Analyse how a market seller tracks sales.
- Improve attendance reporting.

## Output Evidence

- Process map
- Problem statement
- Requirements list
- Proposed solution
- Tool justification
- Before/after explanation
