# Course Blueprints v3

## How to read this document

Each blueprint defines the output a course must produce, its essential competency sequence, three required mission types, and its capstone gate. Mission authors may change the local scenario without weakening the performance requirement.

## 1. Thinking & Problem Solving

**Exit performance:** Diagnose an unfamiliar problem, distinguish causes from symptoms, compare options against constraints, and justify a testable next step.

**Sequence:** observe and question → frame stakeholders and impact → separate fact, assumption, and opinion → decompose → find root causes → generate options → evaluate trade-offs → test and reflect.

**Mission set:** Diagnose repeated stock errors; improve a school queue; independently investigate a learner-selected community problem.

**Capstone gate:** A problem brief containing evidence, stakeholder perspectives, root-cause reasoning, constraints, success measures, alternatives, and a justified recommendation. A proposed app without process diagnosis does not pass.

## 2. Business & Process Analysis

**Exit performance:** Observe and map a real workflow, elicit requirements, identify bottlenecks and risks, and propose a measurable improvement before selecting technology.

**Sequence:** process boundaries → observation/interviews → current-state map → handoffs and failure points → root cause → requirements → future-state map → measurement and change plan.

**Mission set:** Map school attendance reporting; improve a small-business order process; independently redesign a community-service workflow.

**Capstone gate:** Current/future process maps, anonymized evidence, requirements with priorities, bottleneck analysis, tool/no-tool justification, risks, and baseline/target measures.

## 3. AI Communication & Prompt Engineering

**Exit performance:** Use AI purposefully and safely, construct clear prompts, compare outputs, verify important claims, and preserve human agency.

**Sequence:** AI capabilities/limits → privacy and safe input → question quality → context/constraints/output format → iteration → evidence and source checks → bias/assumption review → reusable prompt patterns.

**Mission set:** Improve a weak learning prompt; create and test a planning prompt for a real project; independently produce a verified research or review workflow.

**Capstone gate:** Prompt versions, rationale, outputs, verification record, disclosed limitations, privacy check, and a reflection showing which decisions remained human.

## 4. AI-Assisted Development

**Exit performance:** Plan, build, test, debug, refactor, document, and deploy a small software product with AI assistance while understanding and owning the result.

**Sequence:** problem/requirements → decomposition → bounded prompting → code reading → local testing → debugging → security and dependency review → refactoring → documentation → deployment.

**Mission set:** Critique and repair generated code; rebuild a small tool from a plan with reduced assistance; independently deliver and document a tested product.

**Capstone gate:** Plan, version history, working code, tests, defect log, AI transcript excerpts, dependency/license notes, deployment, and line-by-line explanation of a selected critical section.

## 5. Web Development

**Exit performance:** Design, build, test, and deploy an accessible responsive website that solves a defined user need.

**Sequence:** semantic HTML → CSS and layout → responsive design → accessible navigation/forms/media → JavaScript interaction → data handling basics → Git/version control → testing/performance → deployment.

**Mission set:** Build an accessible personal/profile page; build and test a responsive event-registration experience; independently deploy a community information site.

**Capstone gate:** Live URL, source repository, requirements trace, keyboard test, labels/structure/contrast checks, responsive evidence at 360px, performance check, user feedback, revision, and maintenance notes.

## 6. Python Programming

**Exit performance:** Develop and test a readable Python program that processes input or data to solve a real task.

**Sequence:** values/variables/input/output → conditions → lists and loops → functions → validation/errors → files/CSV → decomposition → testing/debugging → documentation.

**Mission set:** Build an inventory counter; process attendance or sales records; independently create a useful automation or analysis tool.

**Capstone gate:** Running program, representative tests including invalid input, decomposed functions, readable naming, sample data without personal information, defect/revision record, and explanation of the algorithm.

## 7. Data Analysis

**Exit performance:** Turn a messy dataset into a trustworthy, appropriately visualized insight and a bounded decision recommendation.

**Sequence:** question and measures → collection/ethics → table structure → cleaning → formulas/summaries → chart selection → interpretation → uncertainty/limitations → dashboard/story → optional Python/pandas transfer.

**Mission set:** Audit attendance data quality; build a sales or market-price insight; independently analyze a new dataset for a stakeholder decision.

**Capstone gate:** Data dictionary, original and cleaned data, reproducible cleaning log, calculations, appropriate chart/dashboard, claim-evidence links, limitations, privacy check, and stakeholder recommendation. Correlation may not be presented as causation.

## 8. CMS & No-Code Web Building

**Exit performance:** Select, plan, build, hand over, and maintain a CMS/no-code site appropriate to a client's update needs and constraints.

**Sequence:** requirements and tool fit → information architecture → content model → pages/posts/templates → navigation → forms/privacy → responsive/accessibility checks → basic SEO → plugins/security → backup, updates, and handover.

**Mission set:** Plan a training-centre site; build a functional lead-capture or programme site in an external/sandbox CMS; independently deliver a maintainable client-style site and handover pack.

**Capstone gate:** Working site or faithful sandbox build, tool-choice rationale, sitemap/content model, accessible form, SEO basics, performance/responsive evidence, plugin-risk review, backup/update checklist, and client handover guide. A plan alone cannot complete the course.

## 9. Hardware, Automation & Robotics

**Exit performance:** Design and validate a safe virtual automation system using inputs, outputs, control logic, simulation, and failure analysis.

**Sequence:** systems/energy safety → input/output → sensors/actuators → logic and flowcharts → conditions/timing → virtual circuits → debugging → failure states/fail-safe behavior → IoT/privacy concepts.

**Mission set:** Simulate a traffic light; design and test a moisture or fill-level alert; independently simulate an automation solution for a local problem.

**Capstone gate:** System boundary, input/output map, flowchart or pseudocode, working simulation, normal/edge/failure test table, safety analysis, component rationale, demo, and explanation. A diagram without a tested simulation does not complete the course.

## 10. Product & Design

**Exit performance:** Research a user need, define success, prototype a focused solution, test it with users, and revise based on evidence.

**Sequence:** ethical research → interview/observation → synthesis → problem statement → assumptions → value proposition → task flow → low-fidelity prototype → usability testing → prioritization → iteration.

**Mission set:** Improve a confusing school form; prototype a tool for a small-business workflow; independently validate and revise a learner-selected product concept.

**Capstone gate:** Research notes without unnecessary personal data, insight synthesis, explicit assumptions, success measure, prototype, test plan, observed findings, prioritized revision, and evidence that the solution was not predetermined.

## 11. Communication, Presentation & Leadership

**Exit performance:** Explain technical work accurately to different audiences, document it for reuse, respond constructively to critique, and help another learner improve.

**Sequence:** audience/purpose → structure → plain language → visual evidence → demonstration → questions → constructive feedback → documentation → facilitation/mentoring → reflection.

**Mission set:** Explain a build to a peer; present a recommendation to a stakeholder; document and facilitate another learner's successful task.

**Capstone gate:** Audience-specific presentation, live or recorded demonstration, concise documentation, response to questions, received/applied feedback, and tutor-witnessed peer support. Leadership cannot be self-attested.

## Programme-level exit claim

IATECH may describe a learner as a Future Builder only when the portfolio includes:

- one approved diagnosis/process artifact;
- one independently built and tested software or no-code artifact;
- one data-informed decision artifact;
- responsible AI evidence across at least two missions;
- one deployed, externally usable, or fully simulated capstone;
- one recorded revision from critique; and
- one audience-facing explanation or witnessed teach-back.
