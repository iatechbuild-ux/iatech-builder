# Mission Template

> v2.0 restores the guidance and a worked example that v1 stripped to bare headers. Copy this file to author a new mission. Every field is required unless marked optional.

## Header
- **Mission name:** short, memorable, action-oriented.
- **Tier:** `Build` or `Ship`.
- **Pathway:** Explorer / Builder / Innovator.
- **Competencies developed + target level:** e.g., *web-development → Application; critical-thinking → Application.*
- **Estimated time:** realistic on the reference device.
- **Prerequisites:** competencies × minimum level (drives unlocking).

## The problem (problem-first, always)
- **Real-world problem:** describe the situation.
- **Who has this problem:** the specific person/stakeholders.
- **Why it matters:** the human cost of leaving it unsolved.

## The build
- **What learners will build:** the artifact, concretely.
- **Thinking challenge:** the question that must be reasoned about before building (critical/systems thinking).
- **Lessons:** ordered, just-in-time.
- **Activities:** predict-output / debug / compare / build.
- **Build checklist:** the concrete steps to the artifact.

## External AI practice (required)
- **Prepared prompt** (Role + Goal + Context + Constraints + Output format).
- **Safety note** (the standard reminder).
- **Reflection questions**, including the required *"What did the AI get wrong or miss, and how did you check?"*

## Evidence & assessment
- **Submission requirements:** Build-tier → running artifact + screenshot + explanation; Ship-tier → live URL + GitHub link + screenshot; plus AI transcript + reflection for both.
- **Rubric:** reference the standard rubric ([`assessment-rubrics.md`](assessment-rubrics.md)); note any per-mission emphasis.
- **Badge earned:** competency × level.
- **Reflection questions:** what you learned, what failed, what you'd improve.
- **Extension challenge (optional):** a self-directed stretch (evidences Independence/Leadership).

## Worked example (abbreviated)

- **Name:** Never Count Twice
- **Tier:** Build · **Pathway:** Explorer · **Competencies:** python → Application, computational-thinking → Application
- **Problem:** A neighborhood shopkeeper recounts stock every night and keeps making errors.
- **Who:** The shopkeeper (primary); her supplier who trusts the counts (secondary).
- **Why it matters:** Wrong counts cost money and trust; she loses an hour nightly.
- **What learners build:** A small Python inventory counter that adds/removes items and shows a running total.
- **Thinking challenge:** Will a counting tool actually help, or is the real problem *how* she records items during the day? Justify before building.
- **Lessons:** variables & input → lists → loops → simple error handling (each unlocked by the next build step).
- **AI practice:** "Act as a friendly Python tutor. Help me plan a simple inventory counter for a shopkeeper. List the steps and the parts I'll need." → learner must report one thing the AI got wrong for their real case.
- **Submission:** running script + screenshot + explanation of the logic + AI transcript + reflection.
- **Badge:** Python Builder (Application).
