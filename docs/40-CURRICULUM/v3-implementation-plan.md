# Curriculum v3 Implementation Plan

## Decision

Do not launch 11 shallow “courses.” Launch a common core, two primary build routes, and three applied studios, while the remaining domains operate as embedded practices.

## Release 1 — Foundation and Python pilot

**Programme outcome:** An Explorer can diagnose a simple process problem, use AI safely, build and test a small Python solution, and explain the result.

Deliver:

1. Digital-confidence diagnostic and on-ramp.
2. Thinking/problem-framing mini-mission.
3. AI safety, prompting, and verification mini-mission.
4. Complete “Never Count Twice” Python mission with lessons, practice, misconceptions, test cases, and calibration samples.
5. A second Python transfer mission using different data and reduced support.
6. Tutor delivery guide and learner evidence pack.

Exit gate: two Python contexts, one at assistance band C; approved explanation and AI disclosure.

## Release 2 — Web build route

Deliver semantic HTML, CSS/layout, responsive design, forms, JavaScript interaction, accessibility, Git/GitHub, testing, and deployment through three missions. The final mission must ship a useful community-facing website.

Exit gate: live accessible site, repository, tests, user feedback, and independent transfer.

## Release 3 — Applied studios

Deliver one complete three-mission studio each for:

- Data Analysis
- CMS/No-Code
- Virtual Automation/Robotics

Each studio must produce the artifact described in `course-blueprints-v3.md`; a plan or activity checklist alone is insufficient.

## Release 4 — Builder and Innovator depth

Add larger integrated missions, databases/APIs where approved, stakeholder collaboration, portfolio exhibitions, and witnessed leadership tasks.

## Content production workflow

For each release:

1. Author outcome/evidence map.
2. Author transfer capstone first.
3. Author integrated mission and diagnostic.
4. Add lessons and deliberate practice.
5. Create tutor guide and calibration samples.
6. Run internal QA against quality gates.
7. Pilot with at least three representative learners.
8. Revise from observed misconceptions, access barriers, and timing.
9. Only then mark the course outcome-ready.

## Current truth in product messaging

Until these releases pass their gates, describe the platform as a **pilot learning environment** and distinguish:

- Available now
- In pilot
- Planned

Do not present every skill domain in the database as a completed course.
