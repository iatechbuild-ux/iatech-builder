# Research Backlog

> v2.0 reframes this from a flat topic dump into a prioritized queue with a reason each topic matters. A topic is only "ready" when it can be expressed as a tutor move, a mission hook, and a mastery rubric (the bar set in [`../01-RESEARCH/README.md`](../01-RESEARCH/README.md)).

## Prioritization method

Score each candidate on: **(a)** does it deepen the existing learning model? **(b)** can it be taught through missions without new paid infrastructure? **(c)** does it serve the graduate identity? High on all three → promote to `01-RESEARCH` and author full content.

## Near-term (strengthen what exists)

- **Learning science depth** — cognitive load, retrieval practice, spacing: refine mission sequencing and reflection design. *(Directly improves current missions.)*
- **Assessment & feedback science** — how to make tutor feedback reliably formative and consistent across tutors. *(Addresses the tutor-quality-variance risk.)*
- **Motivation** — intrinsic motivation and mastery orientation, to keep gamification honest. *(Guards the anti-gamification stance.)*

## Mid-term (extend the graduate)

- **Data literacy** — reading, interpreting, and presenting simple data; a natural extension of the Python data-summary missions.
- **Cybersecurity basics** — safe accounts, passwords, phishing; reinforces AI/online safety.
- **Entrepreneurship, marketing, sales fundamentals** — serve the "I can create value" capability.
- **Public speaking / storytelling** — deepen the Present + Communicate step.

## Longer-term (new domains, only if the model proves out)

- Mobile development · no-code/low-code · robotics/IoT · leadership curriculum for the Leadership mastery level.

## Rule

No topic enters the curriculum as a "subject." It enters only when it can live inside missions and be assessed through artifacts and explanation.
