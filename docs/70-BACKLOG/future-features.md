# Future Features (Deliberately Deferred)

> v2.0 fixes the v1 contradiction where "not now" read as "not ever" while the roadmap scheduled the same items. **"Not now" means "not in this version."** Each item names the version it is expected in, so there is one consistent story.

## Deferred, with target version

| Feature | Target | Why not now |
|---|---|---|
| Notifications, search, learning journal | V2 | Nice-to-have; core loop must prove out first. |
| Parent weekly digest, admin analytics | V2 | Needs real usage data to be meaningful. |
| Opt-in public portfolios | V2 | Requires consent + safeguarding controls first. |
| Peer review (moderated) | V3 | First learner-to-learner visibility; raises safeguarding bar. |
| Team projects | V3 | Collaboration complexity; needs peer trust model. |
| Leaderboards (improvement-framed) | V3 | Must not undermine "portfolio over certificates." |
| Community challenge library / hackathons | V3 | Depends on a mission authoring pipeline at scale. |
| AI tutor / AI feedback drafts / adaptive practice | V4 | Requires lifting the no-paid-AI constraint deliberately, behind a provider-agnostic layer, with human-in-the-loop preserved. |
| Mentor network, internship matching | V5 | Ecosystem play; needs graduate volume. |
| School partnerships, tutor certification, certifications | V5 | Certifications must attest to portfolio evidence, never replace it. |
| Native mobile apps | V5+ | PWA covers the reference device; native only if a real gap appears. |

## Hard "not in the MVP, no exceptions"

Payments · marketplace · video calls · real-time collaborative editing · robotics/hardware · AR/VR · full social network · complex gamification (streaks, variable rewards) · any paid AI API. Adding any of these to v1 requires a `DECISION_LOG.md` entry retiring the relevant constraint.

## The gate

If an idea does not help validate the core learning loop, it stays here. The backlog is where good ideas wait — not where they die.
